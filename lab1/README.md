## Дані та ініціалізація (`load_data`, `init_params`)

- Iris, 150 квіток, 3 класи по 50. Стратифікований поділ: 35 у навчальну і 15 у тестову вибірку на кожен клас (`default_rng(0)`, перемішування індексів кожного класу). Навчальна вибірка — N = 105.
- Стандартизація: середнє і `std` (`ddof=0`) рахуються лише за навчальною вибіркою й застосовуються до обох.
- Параметри (один `default_rng(0)`: спочатку W1, потім W2): `W1 ~ N(0, 2/4)` (He, fan_in = 4), `W2 ~ N(0, 2/(8+3))` (Xavier), `b1 = 0`, `b2 = 0`.

## 1. Реалізація у NumPy

Прямий прохід:

| Величина | Формула | Розмір |
|---|---|---|
| X | стандартизовані ознаки | (N, 4) |
| W1, b1 | параметри першого шару | (4, 8), (8,) |
| W2, b2 | параметри другого шару | (8, 3), (3,) |
| z1 | X·W1 + b1 | (N, 8) |
| a1 | ReLU(z1) = max(z1, 0) | (N, 8) |
| z2 (логіти) | a1·W2 + b2 | (N, 3) |
| log-softmax | z2' − log Σₖ exp(z2'ₖ), де z2' - зі зсувом на максимум | (N, 3) |
| L | −(1/N) · Σᵢ logp[i, yᵢ] | скаляр |

Зворотний прохід:

| Величина | Формула | Розмір |
|---|---|---|
| dz2 = ∂L/∂z2 | (softmax(z2) − onehot(y)) / N | (N, 3) |
| ∂L/∂W2 | a1ᵀ · dz2 | (8, 3) |
| ∂L/∂b2 | Σ по об'єктах dz2 | (3,) |
| da1 = ∂L/∂a1 | dz2 · W2ᵀ | (N, 8) |
| dz1 = ∂L/∂z1 | da1 ⊙ 1[z1 > 0] | (N, 8) |
| ∂L/∂W1 | Xᵀ · dz1 | (4, 8) |
| ∂L/∂b1 | Σ по об'єктах dz1 | (8,) |

### Підрахунок градієнтів

Позначення індексів: `i` — квітка (1…N), `m` — ознака (1…4), `k` — нейрон прихованого шару (1…8), `j` — клас (1…3). Мережа — ланцюжок `L ← z2 ← (a1, W2, b2)` і `a1 ← z1 ← (X, W1, b1)`. Градієнти обчислюються по ньому від `L` до параметрів.

**Крок 1. Градієнт за логітами `dz2`.**

Для однієї квітки: `z2` — її три логіти, `y` — номер правильного класу, `softmax[j] = exp(z2[j]) / (exp(z2[0]) + exp(z2[1]) + exp(z2[2]))`.

Формула L:

```
L = −z2[y] + log( exp(z2[0]) + exp(z2[1]) + exp(z2[2]) )
```

Похідна за z2 при правильному класі (j = y):

```
∂L/∂z2[y] = softmax[y] − 1
```

Похідна за z2 при неправильному класі (j ≠ y):

```
∂L/∂z2[j] = softmax[j]
```

Для всієї вибірки `L` — середнє за N квітками, тому кожну похідну ділимо на N. Разом: `dz2 = (softmax − onehot) / N`.


**Крок 2. Другий шар `z2[i,j] = Σₖ a1[i,k]·W2[k,j] + b2[j]`.** Локальні похідні: `∂z2[i,j]/∂W2[k,j] = a1[i,k]`, `∂z2[i,j]/∂b2[j] = 1`, `∂z2[i,j]/∂a1[i,k] = W2[k,j]`.

```
dW2[k,j] = Σᵢ dz2[i,j] · a1[i,k]       →  dW2 = a1ᵀ · dz2         (8,N)·(N,3) = (8,3)
db2[j]   = Σᵢ dz2[i,j]                 →  db2 = Σ по об'єктах dz2    (3,)
da1[i,k] = Σⱼ dz2[i,j] · W2[k,j]       →  da1 = dz2 · W2ᵀ         (N,3)·(3,8) = (N,8)
```

Ваги та зсуви спільні для всіх квіток, тому їхні градієнти є сумами за квітками (`Σᵢ`). 

**Крок 3. ReLU `a1 = max(z1, 0)`.** Похідна дорівнює 1 при `z1 > 0` і 0 в іншому разі:

```
dz1[i,k] = da1[i,k] · [z1[i,k] > 0]    →  dz1 = da1 ⊙ (z1 > 0)    (N,8)
```

**Крок 4. Перший шар `z1[i,k] = Σₘ X[i,m]·W1[m,k] + b1[k]`.** Така сама структура, як у кроці 2, але `a1` замінюється на `X`, а `dz2` на `dz1`:

```
dW1[m,k] = Σᵢ dz1[i,k] · X[i,m]        →  dW1 = Xᵀ · dz1         (4,N)·(N,8) = (4,8)
db1[k]   = Σᵢ dz1[i,k]                 →  db1 = Σ по об'єктах dz1    (8,)
```


Порядок обчислень у `backward` збігається з цими кроками: `dz2` → `dW2, db2, da1` → `dz1` → `dW1, db1`. У режимі `error` пропускається лише ділення на N у градієнті за логітами.

## Крок 2. Звірка з PyTorch

Така сама мережа в PyTorch: `nn.Sequential(Linear(4,8), ReLU, Linear(8,3)).double()`. Початкові параметри копіюються з NumPy; `nn.Linear` зберігає вагу як `(out, in)`, тому W1 і W2 копіюються з транспонуванням, а градієнти PyTorch транспонуються назад. Втрата — `F.cross_entropy` (середнє за об'єктами), градієнти — `loss.backward()`. Критерій: `|a − b| ≤ 1e-12`; для градієнтів береться максимум по всіх елементах.

Правильний режим (`results/correct_torch_check.csv`). Втрата NumPy = `1.4562007801142816`, PyTorch = `1.4562007801142818`.

|---|---|---|
| Втрата | 2.220e-16 | так |
| Градієнт W1 | 5.551e-17 | так |
| Градієнт b1 | 3.816e-17 | так |
| Градієнт W2 | 1.110e-16 | так |

## 3. Перевірка окремих градієнтів чисельним диференціюванням

Для одного елемента кожного параметра: `g_num = (L(θ + ε) − L(θ − ε)) / (2ε)`, де змінюється тільки цей елемент, а решта параметрів лишається незмінною. Після обчислення елемент повертається назад. Критерій: `|g_num − g_manual| ≤ 1e-7`.

## Крок 4. Дослід із навмисною помилкою


**Прогноз:**

1. Втрата на тих самих параметрах не зміниться, бо змінено лише підрахунок на зворотньому проході.
2. Усі градієнти збільшаться в N разів, оскільки dz2 збільшився в N разів, а градієнти параметрів прямо залежать від нього. 
3. Перевірки різниці градієнтів еталону та numpy реалізації з помилкою - реалізація в pytorch є усередненою. Також чисельна перевірка окремих градієнтів - ми рахуємо різницю між градієнтами, порахованими в зворотньому проході і чисельними похідними за функцією втрат.

## Висновки

У роботі вручну реалізовано прямий і зворотний проходи двошарової мережі на NumPy та перевірено градієнти до початку навчання. Градієнти виведено за правилом ланцюжка: від `L` до логітів (`dz2 = (softmax − onehot) / N`), далі через другий шар (`dW2 = a1ᵀ·dz2`, `db2 = Σ dz2`, `da1 = dz2·W2ᵀ`), ReLU (`dz1 = da1 ⊙ (z1 > 0)`) і перший шар (`dW1 = Xᵀ·dz1`, `db1 = Σ dz1`). Для цього під час прямого проходу зберігаються `X`, `z1` і `a1`, без яких зворотний прохід неможливий.

Реалізацію перевірено двома незалежними способами. Градієнти й втрата збігаються з PyTorch autograd із похибкою порядку 1e-16 (допуск 1e-12), а з чисельною центральною різницею порядку 1e-10 (допуск 1e-7). Отже, ручний зворотний прохід правильний, і з нього можна починати навчання.

У досліді з навмисною помилкою (без ділення на N у градієнті за логітами) втрата не змінилась, бо прямий прохід лишився тим самим, і перевірка за самою втратою помилки не виявила. Проте градієнти всіх чотирьох параметрів зросли рівно в N = 105 разів, і обидві перевірки градієнтів не пройшли: різниці з PyTorch становили 11–34, а з чисельною похідною 2–14. Так було показано, що лише порівняння градієнтів із незалежним еталоном виявляє помилку в `backward`. Прогноз, зроблений до запуску, підтвердився повністю: помилка випливає з математики, бо без `1/N` отримується градієнт суми втрат, а не їхнього середнього. Навчання з таким градієнтом ішло б із завищеним кроком, тому такі перевірки потрібно виконувати до навчання.
